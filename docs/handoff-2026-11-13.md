### 顺手修掉的一个真实缺陷

`ShelfBindings.remove(workId)` 收的是**宿主稳定 id**（`workStableId(sourceKey, sourceWorkId)`），

已加 `removeFromSource(sourceKey, sourceWorkId)` 在装配层重算稳定 id，并补测试
`ShelfBindingsTest.removeFromSourceRebuildsStableId`。

## 3. 四处生产接线（**已完成，仅作追溯**）

> **状态注记（2026-11-13 夜后）**：本节四处缺口已全部接通，见

以下为接线前的原始描述：数据层都已就绪、都有测试，但缺生产调用方，
所以用户当时**在界面上还用不到**下载、收藏、源更新。按投入产出排序：

### 3.1 下载编排未进生产（影响最大）

- 现状：`createDownloadController(...)`（`app/shared-ui/.../DownloadBindings.kt`）**无任何调用方**；
  `App.kt` 的 `is DownloadsRoute -> NavEntry(key) { DownloadsScreen() }` 用默认空流，下载页恒空。
- 要改：
  1. 双端 `Main.kt` / `MainActivity.kt` 构造 controller，需要四项：
     - `fetcher = KtorRangeFetcher(http, cookies) { nowMs }`（已有，自带白名单/配对 UA）
     - `sink = CallbackDownloadSink(...)`，4 个 lambda 用 `java.io.File` 分片落盘
       （桌面 `~/.kurisa/downloads/<taskId>/<i>.part`、Android `filesDir/downloads/...`；
       两端都是 JVM，可直接用 `File`，**不新增 expect/actual**，符合 ADR-006）
     - `resolveUrls = { task -> (chapters.payload(task.workId, task.chapterId) as? ChapterPayload.Images)?.urls.orEmpty().filter { it.startsWith("http") } }`
       —— 必须过滤 `http(s)`，本地书 URL 是 `path!/entry` 形式，走不了 Range 抓取
     - `domains = { bindings.currentDomains() }`
  2. `App(...)` 增加 `downloads: DownloadController? = null`，`DownloadsRoute` 分支把
     `downloads.tasks.map { it.toUi() }` 传给 `DownloadsScreen(tasks = ...)`，
     并把 `onPause/onResume/onCancel` 接到 `downloads.pause/resume/cancel`（需在 `scope.launch` 里）。
- 注意：`DownloadSink.completedParts` 语义是「已完成分片**数量**」，隐含**分片从 0 连续**。
  `DownloadManager` 的 for 循环按 `skip until urls.size` 递增写入，所以连续成立；
  若将来支持乱序分片，这里要一起改。

### 3.2 「加入书架」无入口（在线书架恒空）

- 现状：`ShelfBindings.addFromSearch(SearchWorkUi)` **无调用方**，所以书架「在线收藏」分区永远是空的。
- 要改：`SearchScreen` 结果行 / `DetailScreen` 顶部加一个动作回调
  （建议 `onAddToShelf: ((SearchWorkUi) -> Unit)?`，null 不显示，保持 feature 不依赖 App 层），
  `App.kt` 接成 `scope.launch { shelf?.addFromSearch(work) }`。
  详情页只有 `WorkDetailUi`（无 cover/kind），可现场构造 `SearchWorkUi(workId, sourceKey, title)`。

### 3.3 「移出书架」无入口

- 现状：`ShelfBindings.removeFromSource` 已写好且测过，但 `ShelfWorkRow` 没有按钮。
- 要改：`ShelfWorkRow` 加「移出」，回调 `(workId, sourceKey)`，App 调 `shelf.removeFromSource(...)`。

### 3.4 源订阅无入口

- 现状：`SourceCatalog.planRepoUpdates(rawIndexJson)` 与 `refreshRepoUpdates(fetchIndex)`
  已可用（`fetchIndex` 由宿主注入，模块**不自己联网**，避免白名单红线），但源管理页没有「检查更新」。
- 要改：`SourcesScreen` 加「检查更新」→ App 提供 `fetchIndex`（用 `SourceHttpClient` 或
  独立 `HttpClient`，**必须先过 `security-audit` 再动白名单**）；结果用 `RepoRefreshUi` 展示。
- 风险：这是唯一会引入「用户输入的任意 URL」的链路，安全评审前不要合并。
- **实施口径（2026-11-13 夜，已落地）**：为避免新增网络出口，`App` 改为接收宿主注入的
  `fetchRepoIndex: (suspend () -> String)?`，**只读本地索引文件**；未注入时返回
  「未配置源仓库索引」并 fail-closed，**不发起任何 URL 请求**，因此本次未触碰白名单红线。
  将来若要真正联网订阅，仍须先过 `security-audit` + `UrlPolicy`。
